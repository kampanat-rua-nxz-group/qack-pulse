# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

QA leads and QA managers.

## Product Purpose

Give the team a single view of the latest Lockbox test automation results, with counts rolled up from modules to repositories to products.

## Positioning

qack-pulse reads existing Playwright reports from GitHub Actions artifacts and aggregates their statistics without requiring changes to the test pipelines.

## Operating Context

The dashboard is generated by a local script using the user's authenticated GitHub CLI. It produces a dashboard, machine-readable JSON, and a history calendar. A GitHub Actions workflow also publishes passcode-protected HTML pages.

## Capabilities and Constraints

- Show test counts, pass rates, run details, stale results, and missing or failed result states at the appropriate level of the hierarchy.
- Keep a local append-only history and show historical trends and workflow-job calendars.
- The HTML, JSON, and history contain counts, names, dates, and run links only; they must not contain test names, request data, or response data.
- Escape values from configuration and GitHub before putting them into HTML.
- Use Node 24 or newer, the GitHub CLI, and no npm dependencies.

## Evidence on Hand

The current implementation and usage instructions are in `src/` and `README.md`. The original approved design is in the Obsidian vault at `02_Projects/qack-pulse/plans/first-draft/design.md`; the repository describes subsequent functionality where it differs from that original design.

## Product Principles

- Make the latest automation state understandable across modules, repositories, and products.
- Distinguish missing or stale results from successful results; do not imply unknown counts are zero.
- Keep the displayed information limited to aggregate results and run context.
- Build on the reports and workflows that already exist.
